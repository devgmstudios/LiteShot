Security

Our pledge to
security and safety.

fortefile is built so that we can't read what you share, and so that it doesn't stick around. These are our commitments. Each one describes how the service actually works, so you can check it.

  • Effective October 28, 2026
  • Report a vulnerability: security@fortefile.com

Encrypted before it leaves your device

LiteShot encrypts every upload on your PC with AES-256-GCM, using a fresh random 256-bit key for each file. fortefile only ever receives scrambled bytes, and the viewer decrypts them in the recipient's browser.

Check it: LiteShot is open source, so you can read the code that encrypts your files.

The key never reaches us

The key lives only after the # in the link. Browsers never send that part to a server, so it isn't in our requests, our storage or anyone's logs. Without it, a file is noise: to us, to our host, and to anyone who asks us for it. The only key we ever hold is one that comes with an abuse report: if the law requires us to preserve the reported file, we keep that key with it.

Check it: open a link with your browser's developer tools on the Network tab. Every request stops at the file ID.

Gone within 24 hours

Every file expires after 1, 12 or 24 hours. Its link stops working the moment time is up, an hourly cleanup erases it, and our storage removes anything older than a day as a backstop. Public search images last an hour at most.

Check it: the viewer shows the time left. Afterwards, the link only says the file is gone.

Delete it any time

The uploading app gets a private delete code. One click in LiteShot's tray menu deletes the file for everyone, immediately. We keep only a SHA-256 hash of the code, so even a leak of our storage wouldn't let anyone delete your files.

Check it: delete an upload, then open its link.

No content logs, no tracking

We don't log file contents, links, keys or IP addresses. There are no analytics, ads, trackers, tracking cookies or third-party scripts on fortefile, and no accounts to build a profile on.

Check it: our pages load nothing from any other website. The Content-Security-Policy header says so, and your browser enforces it.

Locked down by design

Two vendors at most: Cloudflare runs our infrastructure, and Google Lens sees only the searches you start. A strict Content Security Policy, HTTPS everywhere, files that can never run as a web page on our domain, and an open-source client under the MIT License.

Check it: look at the response headers of any fortefile page or file.

How the encryption works

  • Algorithm: AES-256-GCM, which is authenticated: if a single byte of the encrypted file is changed, decryption fails instead of producing altered content.
  • Keys: 256 random bits, made fresh for every file by the uploading app and written into the link after the # (base64url).
  • Format: a random 96-bit IV, then the ciphertext, then the 128-bit authentication tag. That is all the server ever stores.
  • Decryption: in the recipient's browser, with the standard Web Crypto API. The key goes from the link straight to the browser's crypto engine and is never sent anywhere.

How files are stored

  • Where: Cloudflare R2 object storage.
  • File IDs: 128 random bits (22 characters), so links can't be guessed or listed.
  • Expiry: checked on every request, so an expired file is never served. An hourly job erases expired files, and a storage lifecycle rule removes anything older than one day in case that job ever stops.
  • Delete codes: 256 random bits, given only to the uploading app. We store a SHA-256 hash of the code and compare in constant time.
  • Limits: files of up to 25 MiB, and 30 uploads per minute per IP address (per /64 block for IPv6).

How the website is protected

  • Content Security Policy: scripts, styles, images and connections may come only from fortefile.com. No inline scripts, Trusted Types are required for script URLs, and no other site may frame our pages.
  • Self-hosted everything: no fonts, scripts, analytics or animations are loaded from anyone else. Even the player for these badge animations is served from fortefile.com.
  • Transport: HTTPS only, with HTTP Strict Transport Security.
  • No leaks: Referrer-Policy: no-referrer, so the pages you go to next don't learn which fortefile link you came from, and a Permissions-Policy that turns off camera, microphone, location, payment and USB access.
  • Inert files: uploaded files are served with X-Content-Type-Options: nosniff and a sandboxing Content Security Policy, so a file can never run as a page on fortefile.com. Viewer pages and files are marked noindex.

What fortefile can't protect against

Being honest about limits is part of the pledge.

  • Anyone with the full link can open the file until it expires or is deleted. Treat a link like the file itself.
  • Some metadata is visible to us and to Cloudflare: a file's size and times, and the IP addresses that connect.
  • Search images aren't encrypted. “Search similar images” makes a screenshot public for up to an hour. Don't use it for anything sensitive.
  • The devices at each end. Malware on the sender's or recipient's device can read files and links.
  • What recipients do. Once someone opens a file, they can save it or take a screenshot.
  • Other apps. Encryption happens in the uploading app. An app other than LiteShot has to do its part correctly.

Report a vulnerability

If you find a security problem in fortefile or in LiteShot's upload and encryption code, please email security@fortefile.com with a description, the steps to reproduce it, the URLs or code involved and the impact you expect. Our contact details are also published in security.txt. We aim to acknowledge reports within three business days, keep you updated, and tell you when the issue is fixed.

Rules for good-faith research

  • Test only with files and links you created yourself. Don't access, change or delete other people's files.
  • If you come across someone else's data, stop, don't keep or share it, and tell us.
  • Don't degrade the service: no denial-of-service or load testing, and no automated scanning that sends heavy traffic.
  • No social engineering, phishing or physical attacks, and don't test Cloudflare's or Google's own systems (report those to them).
  • Give us a reasonable time to fix the issue (we ask for 90 days) before you publish anything, and coordinate the disclosure with us.

Safe harbor

If you follow these rules in good faith, we consider your research authorized. We won't take or support legal action against you for it, and the security-testing restrictions in our Acceptable Use Policy don't apply to it. If someone else takes legal action against you for research that followed these rules, we'll make it known that your work was authorized. If you're unsure whether something is allowed, ask us first.

We don't run a paid bug bounty program and can't promise rewards. With your permission, we'll gladly credit you when we announce a fix.

How we respond to abuse

We can't read encrypted files, and we won't build a way to: no backdoors and no key escrow. LiteShot's code is public, so a change like that would be visible to everyone. Instead:

  • anyone can report a file to abuse@fortefile.com with its full link, and we use that key only to review the file and act on it;
  • we delete abusive files, block access to them and block uploads from the networks involved;
  • we report child sexual abuse material to NCMEC, as U.S. law requires;
  • we respond to valid legal process, but can hand over only what we have, which our Privacy Policy lists.

The rules and the reporting steps are in our Acceptable Use Policy.

If something goes wrong

If we discover a security incident that affects fortefile users, we'll fix it, post a notice on this page and on the home page explaining what happened and what it means for you, and notify the authorities and affected people where the law requires.
